# 知识经验管理工具：项目背景与方案说明

## 1. 项目背景

在日常生活和工作中，很多重要决策都依赖大量零散经验，例如装修、家电家具选购、旅行规划、育儿、学习、健康管理、买车选车、工作项目复盘等。这些信息通常来自小红书、短视频、聊天记录、网页、商品页、报价单、截图和个人笔记。

这类信息有几个共同问题：

- 收藏很多，但真正要用时找不到。
- 不同来源的信息互相矛盾。
- 经验点缺少适用条件，容易误用。
- 目录和结构需要人工整理，维护成本高。
- 决策过程没有沉淀，事后难以复盘。
- 手机端临时记录方便，但后期整理困难。

以装修为例，用户会持续收集施工经验、材料避坑、家电参数、报价截图、商品型号和最终购买记录。如果没有结构化工具，这些信息很快会变成一堆无法复用的杂乱笔记。

因此，本项目希望做一个通用的知识经验管理工具，帮助用户把零散信息沉淀为可维护、可检索、可审查、可复用的知识图谱。

## 2. 产品定位

本工具不是普通笔记软件，而是一个面向“经验型知识”和“复杂决策”的管理系统。

核心定位：

> 将零散经验、截图、链接、商品信息和个人记录，通过 AI 辅助整理为结构化知识图谱，并支持持续补充、冲突审查和决策沉淀。

装修只是第一个使用场景。未来同一套工具可以支持更多项目，例如：

- 新房装修
- 家电家具选购
- 旅游攻略
- 买车选车
- 育儿经验
- 健康管理
- 学习计划
- 工作项目复盘
- 副业研究
- 投资学习笔记

## 3. 核心思路

系统采用通用层级结构：

```text
工作区 Workspace
  项目 Project
    知识目录 Knowledge Map
      节点 Node
        经验记录 Entry
        来源材料 Source
        附件 Attachment
        决策 Decision
        待办 Task
        AI 审查 Review
```

每个项目都有自己的知识目录。目录可以由用户手动创建，也可以由 AI 根据项目目标自动起草。

每条信息都尽量保留来源，并标记类型：

```text
类型：经验 / 参数 / 避坑 / 商品 / 价格 / 决策 / 待办 / 疑问
来源：截图 / 视频 / 网页 / 手动记录 / 聊天记录
状态：待整理 / 已归档 / 待确认 / 有冲突 / 已采纳
```

系统要解决的核心链路是：

```text
零散输入
  → AI 提取
  → 人工确认
  → 归档到知识目录
  → 持续补充
  → Review 审查
  → 形成决策和经验沉淀
```

## 4. 主要功能

### 4.1 项目管理

用户可以创建多个项目，每个项目独立维护知识目录、资料、记录和决策。

示例：

```text
项目：新房装修
项目：日本旅行
项目：买车调研
项目：育儿知识库
```

项目可以包含：

- 项目目标
- 项目状态
- 知识目录
- 采集资料
- 决策记录
- 待办事项
- Review 问题

### 4.2 AI 起草目录

用户输入项目背景和目标，AI 自动生成初始目录。

例如输入：

```text
我要装修新房，设计方案基本确定，准备进入施工和采购阶段。
```

AI 可以生成：

```text
硬装施工模块
主材与辅材
全屋系统
家具家电
收纳系统
灯光与氛围
预算与采购
施工流程与验收
环保与安全
容易后悔的细节
```

用户可以在此基础上继续调整目录、增删节点、修改层级。

### 4.3 知识目录 / 知识图谱

每个项目都有一个可持续维护的知识目录。

目录可以是多级结构：

```text
一级模块：家具家电
  二级模块：大家电
    三级细项：冰箱
      注意事项
      我的需求
      尺寸限制
      参数记录
      候选型号
      价格记录
      最终选择
```

目录节点不只是普通文本，还可以承载不同类型的信息：

- 注意事项
- 经验记录
- 参数
- 商品
- 价格
- 图片
- 链接
- 决策
- 待办
- 冲突问题

### 4.4 采集箱

用户可以快速收集资料，不必一开始就整理。

支持：

- 上传截图
- 上传图片
- 粘贴网页链接
- 粘贴文字
- 手动快速记录
- 后续扩展：视频、音频、聊天记录（PDF 解析当前暂缓）

采集箱的目标是降低记录成本，让用户先把信息收进来，再由 AI 和人工一起整理。

### 4.5 AI OCR 与信息提取

针对截图、商品页、报价单、小红书笔记截图等，AI 可以自动识别并提取关键信息：

- 标题
- 核心经验
- 参数
- 商品型号
- 品牌
- 价格
- 尺寸
- 风险点
- 适用条件
- 建议归档位置

例如截图里提到“零嵌冰箱要看底部散热”，AI 可以提取为：

```text
项目：新房装修
建议节点：家具家电 > 大家电 > 冰箱
类型：避坑经验
内容：零嵌冰箱需要重点确认散热方式，底部散热和两侧散热的预留尺寸不同。
来源：小红书截图
状态：待确认
```

### 4.6 节点拓展

用户打开某个知识节点后，可以让 AI 基于已有内容继续拓展。

例如在“冰箱”节点下，AI 可以补充：

- 尺寸关注点
- 容量选择
- 散热方式
- 能效
- 噪音
- 开门方式
- 嵌入条件
- 常见坑
- 购买前检查清单

节点拓展不直接覆盖用户原有内容，而是生成建议，用户确认后再写入。

### 4.7 AI Review

系统可以定期或手动对某个项目进行审查，发现问题：

- 重复记录
- 冲突信息
- 缺少适用条件
- 待确认事项
- 决策依据不足
- 参数和实际尺寸不匹配
- 已过期信息
- 高风险节点

例如：

```text
冲突：
记录 A：冰箱两侧要预留 10cm。
记录 B：零嵌冰箱两侧只需要 0.4cm。

AI 判断：
这两条可能不是真冲突，而是适用于不同散热方式。

建议补充前提：
- 普通两侧散热冰箱需要较大侧边空间
- 零嵌 / 底部散热冰箱预留要求以具体型号安装图为准
```

AI Review 的目标不是替用户直接改内容，而是提出问题、解释可能原因，并生成可确认的修改建议。

### 4.8 决策与溯源

> ⚠️ 暂缓（2026-08-07 决定）：决策功能当前阶段不实现。目标场景使用少、复杂度高，产品先聚焦知识采集与整理；
> 本节保留为远期基线，不代表最终不做。

重要信息需要保留来源，避免后续只剩结论却不知道依据。

每条记录可以关联：

- 原始截图
- 原文链接
- 上传文件
- AI 提取结果
- 用户确认记录
- 后续修改历史

最终决策也应单独沉淀，例如：

```text
节点：家具家电 > 大家电 > 冰箱
最终选择：某品牌某型号
购买价格：xxxx 元
购买渠道：京东 / 天猫 / 线下门店
选择原因：尺寸匹配、底部散热、容量合适、价格在预算内
相关来源：商品页截图、门店报价、小红书经验、安装尺寸图
```

### 4.9 预算与花费管理

> ⚠️ 暂缓（2026-08-07 决定）：预算与花费功能当前阶段不实现。目标场景使用少、复杂度高，产品先聚焦知识采集与整理；
> 本节保留为远期基线，不代表最终不做。

部分项目和节点需要管理预算与实际花费，例如装修、旅行、买车、学习设备采购、健康管理等。预算能力应作为通用能力存在，但不强制所有项目使用。

预算可以挂在不同层级：

```text
项目级预算：新房装修总预算 300000 元
一级模块预算：家具家电 80000 元
二级模块预算：大家电 40000 元
三级细项预算：冰箱 12000 元
```

实际花费也应能挂到具体节点，并和来源、决策、附件关联：

```text
节点：家具家电 > 大家电 > 冰箱
预算：12000 元
实际花费：10899 元
购买渠道：京东
付款时间：2026-xx-xx
关联决策：最终选择某品牌某型号
关联附件：订单截图、发票、安装单
```

预算管理需要支持：

- 预算金额
- 预算区间
- 实际花费
- 已支付金额
- 待支付金额
- 付款节点
- 费用类型
- 购买渠道
- 发票 / 收据 / 订单截图
- 关联节点
- 关联决策
- 备注

费用类型可以先保持通用：

```text
材料 / 商品 / 服务 / 人工 / 运输 / 安装 / 订金 / 尾款 / 增项 / 维修 / 其他
```

系统应支持预算汇总和超支提醒：

- 项目总预算 vs 项目总花费
- 一级模块预算 vs 一级模块花费
- 节点预算 vs 节点实际花费
- 已付款 vs 待付款
- 超预算项目
- 未记录实际花费的预算项
- 有付款但缺少发票或凭证的项目

预算和知识记录之间应保持关联，而不是做成孤立账本。比如用户在“冰箱”节点下查看经验、候选型号和最终决策时，也能看到预算、已花费、订单截图和售后信息。

AI 可以辅助做预算 Review：

- 提醒某个模块明显超预算。
- 发现有购买记录但没有归档到节点。
- 从订单截图、报价单、合同中提取金额。
- 对比预算和实际花费，生成超支原因摘要。
- 检查是否有订金、尾款、增项未记录。
- 针对同类候选项，辅助整理价格差异和性价比。

### 4.10 预算统计与分析

> ⚠️ 暂缓（2026-08-07 决定）：预算统计与分析随预算功能一并暂缓。本节保留为远期基线，不代表最终不做。

预算和花费需要支持自动统计。系统应根据项目、知识节点、费用类型、付款状态等维度生成汇总视图。

统计维度包括：

- 项目总预算
- 项目总花费
- 已支付金额
- 待支付金额
- 剩余预算
- 超预算金额
- 预算使用率
- 按一级 / 二级 / 三级节点汇总
- 按费用类型汇总
- 按付款状态汇总
- 未归档支出
- 缺少凭证的支出
- 预算为 0 但产生花费的节点
- 有预算但尚未产生花费的节点

示例：

```text
项目：新房装修
总预算：300000
已花费：186500
待支付：42000
剩余预算：71500
预算使用率：62.2%
```

系统可以在不同位置展示不同层级的统计结果：

- 项目首页：展示项目总预算、总花费、剩余预算、预算使用率和超支提醒。
- 预算页：按目录节点、费用类型、付款状态展示明细和汇总。
- 节点详情页：展示当前节点的预算、实际花费、付款记录、关联订单和凭证。
- Review 页：展示超预算、缺少凭证、未归档支出、待支付尾款等问题。

预算统计不应只是简单加总，还应保留层级关系。例如三级节点“冰箱”的花费，应能汇总到二级节点“大家电”，再汇总到一级节点“家具家电”，最终汇总到项目总预算。

AI 也可以参与预算分析：

- 总结哪些模块超支。
- 解释超支原因。
- 找出未归档支出。
- 根据历史记录预测后续可能支出。
- 提醒某些节点有预算但缺少付款记录。
- 提醒某些支出缺少发票、收据或订单截图。
- 根据已记录的候选项和成交价，辅助判断价格是否合理。

## 5. 阶段规划

当前阶段先聚焦产品方向和核心能力梳理，不急于定义严格 MVP。后续根据实际开发成本、AI 接入效果和第一个真实场景的使用反馈，再决定第一版范围。

优先验证的能力包括：

- 项目管理
- 知识目录树
- 节点编辑
- 采集箱
- 图片上传
- OCR 识别
- AI 信息提取
- AI 建议归档
- 搜索
- 移动端适配
- 基础 Review：重复、冲突、待确认

这些能力不一定全部进入第一版，可以按实现难度和实际价值分阶段推进。

> 暂缓（2026-08-07 决定）：决策、预算/花费与 PDF/合同报价解析当前不推进；第一版聚焦知识采集与整理。

建议先用“装修知识管理”作为样板项目，验证真实使用流程：

```text
创建项目
  → AI 起草目录
  → 收集截图 / 文字 / 链接
  → AI 提取信息
  → 建议归档到节点
  → 用户确认
  → 后续搜索、补充和 Review
```

当装修场景跑通后，再抽象成模板系统，支持更多生活和工作项目。

## 6. AI 接入方案

考虑国内使用环境，AI 能力需要做成可替换 Provider：

```text
AI Provider
  - DeepSeek：文本理解、目录生成、总结、Review
  - 豆包：多模态识别、图片理解、OCR
  - 本地 OCR：作为兜底方案
```

系统内部不直接绑定某一家模型，而是抽象为统一能力：

- 目录生成
- 文本总结
- 图片 OCR
- 图片理解
- 信息提取
- 节点归档建议
- 冲突审查
- 内容改写整理

这样后续可以根据成本、效果、速度切换不同模型。

AI 生成内容应与用户原始内容分开保存，并标明来源和生成时间。用户确认后，AI 建议才进入正式知识库。

## 7. 产品形态

产品建议做成移动端优先的 Web App，同时兼顾桌面端整理效率。

移动端重点：

- 快速搜索
- 快速上传截图
- 快速记录文字
- 快速查看节点注意事项
- 快速确认 AI 提取结果

桌面端重点：

- 调整目录
- 批量整理
- 查看长文档
- Review 冲突
- 做决策复盘

基础导航可以包括：

```text
项目
采集
搜索
Review
我的
```

项目内部可以包括：

```text
目录
资料
记录
决策
问题
```

## 8. 数据对象初步设计

核心对象可以包括：

```text
users：用户
workspaces：工作区
projects：项目
nodes：知识节点
entries：记录内容
sources：来源材料
attachments：图片 / 文件 / 截图
ai_extractions：AI 提取结果
reviews：AI Review 结果
conflicts：冲突记录
decisions：最终决策
tasks：待办事项
budgets：预算
expenses：实际花费
payments：付款记录
templates：项目模板
```

其中 `nodes` 是知识图谱的骨架，`entries` 是挂在节点下的具体经验、参数、商品、价格和决策材料。

一条记录可以有多个来源，一个来源也可以被 AI 提取成多条记录。

预算和花费可以关联到项目或任意知识节点。实际付款记录可以继续关联到附件、来源材料和最终决策，方便后续复盘、报销、售后和质保查询。

## 9. 产品价值

这个工具的核心价值不是“保存信息”，而是帮助用户完成：

```text
零散输入 → 结构化整理 → 持续补充 → 冲突审查 → 决策沉淀
```

它解决的是复杂项目中最常见的问题：信息很多，但真正到决策时仍然混乱。

通过 AI 起草目录、OCR 提取、自动归档建议和 Review 审查，工具可以显著降低整理成本，让用户把注意力放在判断和决策上，而不是反复复制、粘贴、归类和翻找。

第一阶段可以先以“装修知识管理”为样板项目，把真实使用流程跑通；后续再抽象成通用模板系统，支持更多生活和工作项目。
