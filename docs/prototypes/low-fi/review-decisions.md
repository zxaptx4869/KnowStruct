# KnowStruct 低保真原型评审决定

以下决定按编号回复即可，例如“1A、2A、3B”。每项的推荐方案均已体现在原型中。

### 决定 1：全局导航

推荐方案：桌面端固定“项目、采集箱、搜索、Review（P1）”，账号入口置底；决策和预算仅在项目内。

选择理由：全局导航只承载跨项目任务，避免把项目私有对象提升为全局概念。

原型对应页面：D01、D04、D06、D08、D09。

其他方案：A. 所有功能都放全局导航；B. 只保留项目，其他入口全部项目内。

需要我确认：是否接受推荐方案，尤其是决策和预算不进入全局导航？

### 决定 2：移动端底部导航

推荐方案：保留“项目、采集、搜索、Review、我的”五项，采集居中强化，Review 标记 P1。

选择理由：覆盖手机高频采集和查询，同时提前验证 P1 入口容量；目录留在项目内部。

原型对应页面：M01-M08。

其他方案：A. P0 隐藏 Review，改为四项；B. 移除“我的”，Review 放在项目内；C. 只保留项目、采集、搜索三项。

需要我确认：P0 原型之后，正式 P0 是否继续显示 Review 占位？

### 决定 3：项目工作区栏数

推荐方案：桌面端三段式：全局导航 + 项目目录/筛选栏 + 主内容区。

选择理由：目录与内容持续并置，支持扫描和切换；来源仅按需打开右侧抽屉，不常驻第四栏。

原型对应页面：D02、D03、D04、D05。

其他方案：A. 全局导航 + 主内容两栏，目录进入独立页；B. 全局导航 + 目录 + 内容 + 常驻来源四栏。

需要我确认：是否接受三段式，且来源不常驻？

### 决定 4：采集箱归属

推荐方案：全局采集箱为主入口，项目内提供带预选项目的“添加资料”快捷入口，两者写入同一采集箱。

选择理由：手机临时采集不必先导航到项目，桌面项目内采集又能减少后续归类。

原型对应页面：D04、M02、M03。

其他方案：A. 仅全局采集；B. 仅项目内采集；C. 全局和项目分别维护两套列表。

需要我确认：是否接受“一套采集箱、两个入口”？

### 决定 5：上传时是否必须选择项目

推荐方案：采集时项目可选，保存为“未分配”；打开 AI 确认时或生成正式记录前必须选择项目。

选择理由：降低手机采集阻力，同时保证 Entry、Node 和项目边界明确。

原型对应页面：M02、M03、M05、D05。

其他方案：A. 上传前必须选项目；B. 永远不要求项目，允许全局正式记录；C. AI 自动选择且无需用户确认。

需要我确认：项目选择的强制时点是否放在归档前？

### 决定 6：资料和正式记录是否独立

推荐方案：项目内保留独立“资料”和“记录”视图；节点详情默认展示正式记录，关联资料从记录进入。

选择理由：Source 有处理状态，Entry 有知识状态和目录归属；合并会模糊“候选”和“正式”的界线。

原型对应页面：D02、D03、D04、D07。

其他方案：A. 合并为“内容”页，用类型筛选；B. 只保留资料页；C. 只保留目录，资料全部从节点进入。

需要我确认：是否接受两个独立视图及其术语？

### 决定 7：Review 归属

推荐方案：全局 Review 聚合全部项目，项目内 Review 是带当前项目过滤的同一队列。

选择理由：用户既需要跨项目看待办，也需要在整理某个项目时保持上下文，不应形成两套 Finding。

原型对应页面：D08，以及 D02/D09 项目标签。

其他方案：A. 仅全局；B. 仅项目内；C. 两套独立 Review 数据。

需要我确认：是否接受“两个入口、同一队列”？

### 决定 8：AI 提取确认方式

推荐方案：候选逐条接受或拒绝；桌面支持连续处理，移动端一屏一条；所有候选有决定后才能“完成本资料”。

选择理由：同一 Source 的候选质量可能不同，整批确认容易把错误或缺少条件的内容写入正式知识。

原型对应页面：D05、M05。

其他方案：A. 默认整批确认；B. 先整批勾选，再一次提交；C. 高置信度自动归档。

需要我确认：P0 是否明确不提供“一键全部接受”？

### 决定 9：来源预览方式

推荐方案：桌面默认右侧抽屉，并提供独立详情页；移动端使用整页预览。

选择理由：桌面保留记录/搜索上下文便于对照，移动端整页更可读；独立页便于从链接直接进入和处理失效状态。

原型对应页面：D03、D06、D07、M08。

其他方案：A. 双端都独立页；B. 双端都抽屉；C. 来源固定为项目工作区第三内容栏。

需要我确认：是否接受端侧差异化方案？

### 决定 10：P1 入口是否提前展示

推荐方案：Review 在全局和移动导航显示并标记 P1；决策、预算只在项目内显示 P1 标签；入口可打开方向稿，不显示不可用按钮。

选择理由：能验证整体扩展性和导航容量，又不会让用户误认为 P0 已实现完整能力。

原型对应页面：D08、D09、移动端底部导航。

其他方案：A. P0 完全隐藏 P1；B. 所有 P1 均显示禁用占位；C. P1 与 P0 同等展示。

需要我确认：正式 P0 是显示标记后的入口，还是完全隐藏？
