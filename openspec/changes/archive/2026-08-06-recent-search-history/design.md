## Context

搜索页（`frontend/src/pages/SearchPage.tsx`）当前为纯前端交互：300ms 防抖自动搜索，关键词与 URL `?q=` 双向同步，空态只显示“输入关键词开始搜索”引导。后端 `GET /api/search?q=` 只负责检索，不感知页面历史。全仓库尚无 localStorage 使用；认证上下文（`useAuth`）提供 `user.id`，可用于按用户隔离浏览器本地数据。

本 Change 在现有搜索页上叠加“最近搜索历史”：空态展示最近搜索列表、点击回填重搜、单条删除、一键清空。已确认的行为细节：最多 8 条、localStorage 存储、同一关键词去重置顶、空词不记录、无结果也算一次搜索、搜索失败不记录、URL 恢复关键词的搜索同样记录、历史项不显示时间、清空无需确认。

## Goals / Non-Goals

**Goals:**
- 空态展示最近搜索（最多 8 条），无历史时保持现有引导。
- 点击历史项回填关键词并触发搜索；重复搜索同一关键词只保留一条并置顶。
- 单条删除与一键清空均为本地即时生效，无需后端与确认弹窗。
- 纯前端实现，无接口、无数据模型、无迁移；localStorage 异常时静默降级，不影响搜索主流程。

**Non-Goals:**
- 不做“最近查看”（功能结构 G6 的其余部分，仍属 P1）。
- 不做跨设备/浏览器同步、服务端存储、搜索统计或订阅提醒。
- 不在历史项上展示时间或筛选条件。

## Decisions

### 1. 存储：localStorage，键按用户隔离

键为 `knowstruct.search.history.<userId>`，值为 JSON 数组 `[{ keyword, searched_at }]`，新条目在前，最多 8 条。

- 理由：需求是轻量的页面便利，localStorage 零后端成本；按 `user.id` 隔离避免同一浏览器多账号混历史；`searched_at` 备用，便于未来展示相对时间。
- 备选：后端按 Workspace 落表——需要接口、迁移与数据隔离处理，超出“显示最近若干条”的比例，否决。
- 兼容：读取时校验数组结构并过滤非法条目；若未来格式变更，更换键名即可，旧键残留无害。

### 2. 记录时机：搜索请求成功返回即记录

在 `useSearch` 返回 `isSuccess`（含空结果集）时记录该关键词；失败状态不记录。URL 恢复关键词触发的成功搜索同样记录（与“每次实际执行的搜索都记录”一致）。

- 理由：贴合“无结果也算一次搜索”的确认口径，实现简单；失败不算有效搜索，重试成功后自然置顶。
- 防重复：记录 effect 以 `[keyword, searchQuery.data]` 为依赖并做幂等守卫（ref 记录最近一次已写入的关键词），避免 React StrictMode 双执行或同数据重渲染导致的重复写。
- 已知取舍：输入过程中停顿超过 300ms 会产生中间词（如“冰”先于“冰箱”），已确认接受（方案 A）。
- 备选：Enter/离开页面时记录最终词——历史更干净但需引入提交语义，与现有自动搜索交互不一致，否决。

### 3. 纯逻辑模块 `frontend/src/search/history.ts`

提供 `readHistory(userId)`、`addSearch(userId, keyword)`、`removeSearch(userId, keyword)`、`clearHistory(userId)`：

- `addSearch` 对关键词 trim；空词直接返回现状；与现有条目 trim 后精确匹配则删除旧条目并置顶；新条目 `unshift` 后截断至 8 条。
- 所有函数内部 try/catch localStorage 读写异常，异常时返回当前内存态或空数组，保证搜索页不因存储问题报错。
- 理由：纯函数便于单测，与组件解耦；删除按关键词定位（去重保证唯一）。

### 4. 界面：空态区块 + 现有状态机不变

在 `SearchPage` 内新增 `SearchHistory` 子组件（沿用 EntryCard/SourceCard 同文件子组件惯例）：

- 条件：`!hasKeyword && history.length > 0` 时渲染“最近搜索”区块；无历史时渲染现有引导面板。
- 区块头部：标题“最近搜索” + “清空”按钮；列表每项为关键词按钮 + 独立删除按钮（stopPropagation）。
- 点击关键词：`setInput(keyword)`，复用现有防抖与 URL 同步路径，不新增搜索入口；该词因再次成功搜索而置顶。
- 删除/清空：直接更新内存态并回写 localStorage，无确认弹窗。
- 样式：复用现有页面容器与按钮类，新增少量 `.search-history*` 类；移动端删除按钮保证可点区域（≥44px）。
- 理由：空态替换为“历史优先、无历史才引导”，与基线 6.5“显示最近搜索或引导”一致，且不触碰加载/失败/无结果/结果各态。

## Risks / Trade-offs

- [中间词噪音] → 已确认接受；去重置顶保证列表不会无限膨胀。
- [localStorage 被清空/隐私模式不可写] → 读写异常捕获后静默降级，历史不显示，搜索不受影响。
- [多账号共用浏览器] → 键按 `user.id` 隔离；退出登录不清理历史，换账号后各自独立。
- [React StrictMode 或缓存重渲染导致重复记录] → 记录 effect 幂等守卫。
- [历史关键词明文存浏览器] → 搜索词非核心业务数据，P0 可接受；不写入后端日志。

## Migration Plan

- 无数据模型变更、无数据库迁移；纯前端随版本发布。
- 回滚：整体回退该提交；历史区块消失，遗留 localStorage 键无害（新代码读取时会过滤或忽略）。
