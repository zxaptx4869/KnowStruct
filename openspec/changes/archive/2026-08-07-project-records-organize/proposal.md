## Why

确认候选时选择「暂不归档」的正式记录，之后既没有地方查看（项目内只有节点级记录列表，未归档记录不在任何节点下），也没有编辑入口去补录归档——记录一旦生成就失去维护入口。同时，正式记录缺少批量整理能力：移动、删除只能逐条在节点内操作。产品聚焦「采集与整理」，项目级记录列表与整理模式是记录维护的自然下一步。

## Appetite

一个垂直切片，投入约 2-3 天：1 个后端项目记录列表端点（含未归档计数）+ 项目工作区「查看/整理」双模式 UI + 多选批量移动/删除 + 复用现有记录编辑对话框 + 自动化测试与浏览器验收。不需要数据库迁移。

## What Changes

- 后端新增项目级记录列表接口：`GET /projects/{project_id}/entries`，返回项目全部正式记录（含未归档），按创建时间倒序，携带节点路径、来源数量；同时返回总数与未归档数。
- 项目详情/列表响应增加记录总数与未归档数（顶栏展示）。
- 项目工作区引入「查看/整理」双模式（桌面与移动端）：
  - 查看模式（默认）：维持现状，点击目录树为导航。
  - 整理模式：右侧切换为项目全部记录列表；目录树变为单选筛选器，顶部提供「全部记录」「未归档」两个伪选项；选中节点即筛选，再次点击取消回到全部。
  - 模式切换按钮：查看模式显示「批量整理」，整理模式显示「回到查看」；模式与筛选状态写入 URL query，刷新/后退不丢。
- 整理模式支持多选与批量操作条：批量移动到节点、批量删除（原子整批，任一校验失败整批拒绝）。
- 单条记录编辑复用现有「编辑记录」对话框（含归档节点下拉，可补录归档/改节点/清空为未归档）。
- 所有编辑与批量操作即时落库生效；「回到查看」仅退出模式，不承担保存职责。

## Capabilities

### New Capabilities

- 无（全部能力归入现有记录维护能力）。

### Modified Capabilities

- `entry-maintenance`：新增「项目级记录列表与整理模式」Requirement，覆盖项目记录聚合查询、未归档可见与补录、目录树筛选、批量移动/删除、记录统计。

## Impact

- 后端：`projects.py` API 与 service 新增项目记录列表与统计查询；`NodeEntryResponse` 增加节点路径；`ProjectResponse` 增加记录/未归档计数；无模型变更、无迁移。
- 前端：`ProjectDetailPage` 增加模式状态与整理视图、目录树筛选伪选项、多选批量条；`projects/queries.ts` 与类型扩展；复用 `EntryEditDialog`。
- 测试：后端 pytest 覆盖列表/计数/批量移动/删除/校验；前端测试覆盖模式切换、筛选、批量操作与补录归档。
- 文档：归档后同步 `entry-maintenance` 主规格（移除「项目级记录列表属后续切片」表述）。
