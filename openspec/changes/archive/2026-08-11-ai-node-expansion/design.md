## Context

KnowStruct 已有项目级「AI 起草目录」（C6）：空项目内生成候选树、澄清、会话式微调（完整目标树 + `apply_directory_tree` 工具）、意图说明折叠、确认创建、单活跃草稿并发规则。节点级「AI 节点拓展建议」（C7）复用这套机制，把目录建设从「一次性起草」扩展到「已有节点下持续生长」。

现状约束：
- `DirectoryDraft` / `DirectoryDraftNode` / `DirectoryDraftMessage` 承载草稿、候选树与会话，草稿归属项目，同一项目至多 1 条活跃草稿。
- 正式目录树遵守：最大 6 层、同级标准化名称唯一、名称 1-100 字符、说明 ≤1000 字符、受保护删除（子树存在受保护 Entry 引用时阻止删除）。
- 节点说明仅由 AI 起草确认时写入，手动界面不提供说明编辑。
- 采集候选的 `suggested_node_path` 为 AI 自由文本，与现有目录无关（后续切片再做归档节点建议增强，本次不做）。

## Goals / Non-Goals

**Goals:**
- 用户可在任意节点详情页发起 AI 拓展，AI 基于项目背景、节点现有子树与 Source 摘要生成目标子树。
- 差异确认面板清晰区分「新增 / 保留 / 建议移除」，移除为高危操作且受保护删除规则约束。
- 会话式微调、意图折叠、生命周期、并发规则与 C6 一致，用户无需学习新交互。
- 桌面与 390px 移动端均可用，入口不额外占行。

**Non-Goals:**
- 不做「采集时建议归档节点」增强（后续切片）。
- 不做自动新建节点：所有新增/移除必须经用户确认。
- 不做节点自身（目标节点）的改名、删除或移动；AI 只作用于目标节点的子树。
- 不引入图数据库、不改变 Source/Extraction/Entry 分层。
- 不修改手动节点创建/编辑/移动/删除的既有规则。

## Decisions

### D1：草稿模型扩展而非新建独立机制

`DirectoryDraft` 新增可空列 `target_node_id`（外键指向 `nodes.id`）：
- 空 = 项目级起草（C6 现有行为，入口不变）。
- 非空 = 节点级拓展（C7），差异与合并基于目标节点的子树。

**备选**：新建独立 `NodeExpansion` 表与独立 API。不选：会复制整套澄清/会话/意图/生命周期机制，且「项目内至多 1 条活跃草稿」的并发规则需要双份实现。

### D2：AI 目标树 = 目标节点下的 children，不含目标节点自身

拓展调用中，AI 输出目标节点的**子节点数组**（嵌套 children），目标节点自身的名称与说明由系统固定。原因是：目标节点是用户当前正在查看/整理的对象，不应被 AI 改名或删除；限制输出范围也减少模型犯错空间。

提示词要求：目标节点现有子树 MUST 完整保留在目标树中（除非确有必要移除），新增节点插入到合适位置。

### D3：递归差异计算 + 移除默认不执行

差异按标准化名称匹配（与同级唯一规则一致）：
- 仅存在于 AI 目标树 → **新增**（整棵新子树）。
- 两边都存在 → **保留**，其 children 递归计算差异。
- 仅存在于现有树 → **建议移除**，默认不勾选，需用户逐个显式确认。

差异面板递归展示到整棵目标子树；「移除」项若节点子树存在受保护 Entry 引用，则标记为不可移除并显示阻断数量。

**备选 A（只对比第一层）**：差异简单，但 AI 无法对保留节点内部做细化，价值打折。
**备选 B（移除默认执行）**：操作风险高，误报移除会破坏正式目录，不选。

### D4：合并落库 = 单事务，新增与移除统一校验

确认时在一个事务内：
1. 校验目标节点仍存在且属于该项目（否则草稿失效并提示重新发起）。
2. 创建所有确认的新增节点（含说明），复用深度、同级重名与归属校验。
3. 删除用户确认移除的节点子树，复用受保护删除校验；任一移除项存在受保护引用 MUST 整批回滚并列出阻断数量与路径，保持草稿可编辑供用户取消勾选后重试。
4. 重复提交幂等（返回原结果，不重复创建/删除）。

与 C6「任一节点失败整批回滚」保持一致。

### D5：复用既有 drafts API 与草稿状态机

扩展 `POST /api/projects/{project_id}/drafts`：请求体新增可选 `target_node_id`，为空时保持 C6 行为。草稿 payload 增加：
- `target_node_id`：区分起草/拓展。
- `diff`：差异快照（新增/保留/移除递归结构），在待确认态返回，供前端差异面板渲染。

澄清、消息、确认、放弃、重试端点与状态机（起草中/待澄清/待确认/起草失败/已确认/已放弃）完全复用。会话消息、意图折叠、10 轮压缩、30 轮上限、超时与连接重试、JSON 容错均沿用。

### D6：并发规则与入口

- 同一项目至多 1 条活跃草稿（起草或拓展共用名额）。
- 存在活跃草稿时，节点详情页的 ✨ 入口隐藏（已有草稿面板展示「继续处理/放弃」），避免多条草稿并存。
- 手动创建节点时仍弹「创建节点将放弃当前 AI 草稿」确认；删除目标节点时，指向该节点的活跃拓展草稿置为已放弃（差异基准失效，不能继续确认）。

### D7：前端入口与差异面板

- 入口：node-hero 编辑按钮（✏️）右侧新增 ✨ 图标按钮，`aria-label`/`title` 为「AI 拓展建议」；移动端 node-head 同位置。
- 差异面板：复用 `DraftPanel`，拓展模式渲染差异树——新增（绿色+）、保留（灰色折叠）、建议移除（红色、默认未勾选、受保护项禁用并显示数量）；可展开查看递归差异；下方为会话区与「确认采用」。
- 有活跃草稿或未选中节点时不渲染入口。

## Risks / Trade-offs

- [AI 遗漏现有子树部分节点 → 被误判为「建议移除」] → 提示词显式要求完整保留现有子树；移除默认不执行，需逐项确认；差异面板明确标出移除后果。
- [差异面板在深层大树上渲染性能/复杂度] → 保留项默认折叠，只展示第一层变化与计数，点击展开递归差异。
- [目标节点在草稿存活期间被删除/移动] → 确认前重新校验目标节点存在且父链未变化，失效则草稿置已放弃并提示重新发起。
- [并发名额共享导致用户在节点页看不到起草入口] → 入口隐藏同时草稿面板提供「继续处理」，跳转/滚动到草稿面板，行为与 C6 空项目态一致。
- [AI 输出包含同级重名或超层 → 整批失败] → 复用 C6 有界重试与人工提示，候选树保持可编辑。

## Migration Plan

1. Alembic 迁移：`directory_draft` 新增可空 `target_node_id`（FK `nodes.id`，`ON DELETE SET NULL`）并建索引；回滚删除该列即可，既有草稿数据不受影响。
2. 发布顺序：先合并并部署后端迁移与接口，再部署前端（前端对旧接口向后兼容，`target_node_id` 缺失时按项目级起草处理）。
