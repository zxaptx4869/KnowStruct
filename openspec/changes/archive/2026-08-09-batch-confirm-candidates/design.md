## Context

当前闭环的最后一步是逐条确认：确认页（`/inbox/:sourceId`）对每条 Extraction 候选提供编辑、接受、拒绝；单条决定通过 `POST /sources/{source_id}/extractions/{extraction_id}/decide` 完成，接受时在同一事务内创建 Entry、EntrySource，更新候选为 accepted 并将 Source 归属到所选项目。采集箱已有来源级批量操作（分配/删除/重试），语义为整批原子：任一元素不满足前置条件则整批拒绝，不产生部分成功；单批上限 100 条 Source。

批量确认是新的人工确认形态：授权粒度在来源层（用户勾选来源），安全校验在候选层（仅高置信度待确认候选可入库），不改变单条确认行为，也不需要迁移。

## Goals / Non-Goals

**Goals:**
- 桌面端采集箱提供来源级「批量确认」：一次勾选多条待确认 Source，弹窗预览后一次性归档其中的高置信度候选。
- 保持既有护栏：AI 候选不直接覆盖正式记录（用户显式批量授权）；低置信度候选（confidence < 0.7）绝不纳入批量；条目可溯源。
- 整批原子：任一来源/候选不合法则整批拒绝，不留部分 Entry；重复提交不重复创建。
- 复用现有模式与模型，不引入数据库迁移。

**Non-Goals:**
- 不做批量拒绝（当前单条拒绝无撤销，批量拒绝不可逆风险过高）。
- 弹窗内不做候选级操作、不做跳转出口（中途跳出会打断批量操作）。
- 移动端（390px）不提供批量确认入口。
- 不做可调置信度阈值、不做批量编辑内容、不改 AI 提取逻辑、不改单条确认行为。

## Decisions

### 1. 端点：来源级批量确认，候选由服务端按规则选择

新增 `POST /sources/batch/confirm`，请求体 `{source_ids, project_id, node_id?}`。服务端对每条选中 Source 选择其 `pending_confirm` 且 `confidence >= 0.7`（`confidence IS NULL` 视为满足）的候选纳入批量；低置信度候选保持待确认并在响应中计数。

**备选**：请求体携带 `extraction_ids`（候选级指定）。否决：与来源级授权模型不一致，会让弹窗退化成候选级勾选界面，违背本切片初衷。

### 2. 预览数据复用现有 Source 详情接口

弹窗打开时前端对选中 Source 并发拉取 `GET /sources/{id}`（分片并发，如每片 10 条），从详情中的 `extractions` 计算可确认候选、低置信度候选与来源级勾选状态。提交时后端重新校验，不以客户端计算结果为准。

**备选**：新增批量预览端点。否决：增加 API 面与测试面，现有详情接口已含所需字段，100 条上限下分片并发可控。

### 3. 整批原子与幂等

单事务：先对全部选中 Source 行加锁（`with_for_update`，沿用单条 decide 的锁模式），依次校验——Source 属于当前 Workspace、处理状态为待确认（`pending_confirm`）、每条 Source 至少有一条可确认候选、项目属于 Workspace、节点（若提供）属于项目、全部候选总数不超过 200；再为每条可确认候选创建 Entry 与 EntrySource、标记候选 accepted、更新 Source 项目归属，最后提交。任一校验或创建失败即回滚，返回可读冲突。重复提交同一批时 Source 已非待确认，整批返回冲突，不创建第二条 Entry。

### 4. Entry 内容取自候选现值

批量确认不提供编辑入口，Entry 的标题、内容、类型与适用条件全部取候选现值；归档状态为 `archived`，节点为空或用户所选统一节点。该行为与单条 decide 的「未编辑字段取候选」一致，只是编辑被整批跳过。

### 5. 前端：批量工具栏 + 确认弹窗（仅桌面）

采集箱批量工具栏新增「批量确认」按钮，仅当选中项中存在待确认 Source 时可用。弹窗（新组件）包含：来源级勾选列表（默认全选，无可确认候选的来源禁用并提示）、只读候选预览（标题/类型/置信度，低置信度标灰标注「不纳入批量」）、项目下拉（必选）与统一节点下拉（可选，默认「暂不归档」）、实时计数按钮「确认生成 N 条正式记录」。提交失败保留弹窗全部状态并允许重试；成功关闭弹窗、toast 汇总、刷新采集箱列表。移动端列表卡片无勾选入口，批量入口自然不可见，与现有批量操作一致。

### 6. 置信度阈值固定 0.7

沿用前端现有低置信度标记（`confidence < 0.7`）与后端校验一致；前端展示与后端判定共用同一阈值常量（前后端各一份，测试锁定一致）。本次不做可调阈值。

## Risks / Trade-offs

- [批量入库内容未经逐条审查] → 低置信度候选强制排除；弹窗只读预览让用户看到「将生成什么」；文案明示按候选内容生成、可事后编辑、并进入 Review 检查范围（缺条件/重复/冲突）。
- [大事务锁竞争] → 单批来源上限 100、全部候选上限 200；来源行锁串行化同批并发。
- [用户误勾选整批归档] → 弹窗内来源级取消勾选 + 按钮实时显示生成数量；记录生成后仍可单条编辑/删除，误操作可恢复。
- [重复/并发提交造成重复 Entry] → 事务内状态校验 + 行锁，第二次提交按非待确认整批冲突处理，不重复创建。
- [前端并发拉取详情请求多] → 分片并发（每片 10 条），100 条上限下最多 10 片。

## Migration Plan

无数据库迁移。前后端同版发布：后端新增端点与校验，前端新增按钮与弹窗；回滚为移除按钮与端点即可，已生成的 Entry 不受影响。

## Open Questions

无阻塞项。候选总数上限 200 与置信度阈值 0.7 为本次固定值，后续可按使用反馈调整。
