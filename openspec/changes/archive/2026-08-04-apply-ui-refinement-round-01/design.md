## Context

当前前端已完成 P0 的功能骨架：登录、项目列表（表格/卡片）、项目工作区（dnd-kit 目录树、节点弹窗、拖拽与菜单）均已实现，后端 API 与主规格同步。第一轮 UI 设计稿（`docs/prototypes/ui-refinement`）已完成评审，明确了视觉 token、页面布局、按钮层级和若干交互/文案决定。本次设计解决"把评审稿落地到真实前端"，同时处理三处与主规格冲突的产品决定。

## Goals / Non-Goals

**Goals:**

- 落地 Round 01 视觉基线：全局 token（主色 `#2767D8`、页面背景、文字层级、4-8px 圆角、语义状态色），桌面与 390px 移动端一致生效。
- 落实设计稿确定的交互：项目列表头部与空状态、创建项目按钮位置与尺寸、工作区单一主操作、节点弹窗字段、空状态文案、移动端节点菜单入口、移动端顶栏布局。
- 通过 delta spec 把三处产品行为变更（无项目空状态、项目目标与背景合并、节点说明仅展示）写进主规格，保持规格与实现一致。
- 覆盖桌面（1440/1280）与 390px 移动视口的真实验收，更新受影响的测试。

**Non-Goals:**

- 登录页"最近维护"上下文面板的数据内容：认证前不得暴露任何业务数据（主规格要求业务 API 必须认证），登录页仅做视觉细化。
- 不新增 AI、Review、采集等 P1-P3 功能；不引入新依赖（图标沿用 lucide-react，拖拽沿用 dnd-kit）。
- 不做后端 API/模型迁移：`background`、`description` 字段保留在数据模型中，仅前端不再暴露编辑入口。
- 不把"轻量 UI 规范"页面（设计稿的 spec 页）实现为产品页面，它只是设计参考。
- 不动 `docs/prototypes/ui-refinement` 设计稿本身（本轮只改真实前端与规格）。

## Decisions

### 1. 视觉 token 以 `frontend/src/index.css` 的 `@theme` 为准

按设计稿"轻量 UI 规范"更新 `@theme`：主色 `#2767D8`（hover `#1f58bd`）、页面背景 `#eef1f4`、主表面 `#ffffff`、文字三级层级、语义色（成功/警告/危险）与 4-8px 圆角；`index.css` 中散落的硬编码色值同步收敛到 token。替代方案（新建独立 tokens 文件）被否：当前 CSS 已集中在 `index.css`，单文件收敛改动面最小。

### 2. 登录页只做视觉细化，不实现认证前的数据面板

设计稿桌面左侧"最近维护"面板需要认证后的项目/目录数据，而登录页在认证前访问，若通过公开接口暴露会破坏"业务 API 必须认证"的安全边界。决定：登录页保持现有居中面板结构，按新 token 与表单状态（默认/错误/加载中）细化；左侧品牌/价值面板留作开放问题，需要时以纯静态内容实现。

### 3. 项目"目标与背景"合并为单个字段，映射到现有 `goal`

创建/编辑项目弹窗把两个 textarea 合并为"项目目标与背景"（最多 500 字符），提交时写入 `goal`；`background` 字段保留在模型与 API 中，但不通过 P0 界面暴露。替代方案（数据库迁移合并/删除 `background`）被否：涉及 Alembic 迁移与 API 破坏性变更，超出本轮"UI 落地"范围；保留字段为后续能力（如 AI 生成背景）留空间。验证规则按合并字段 ≤500 字符更新。

### 4. 节点说明仅展示，不在 P0 提供编辑

创建/编辑节点弹窗只保留名称字段；说明由后端返回并在节点头部/子节点列表展示，不做编辑入口。替代方案（保留编辑字段）与设计评审决定冲突，被否。说明字段继续保留在模型中，供后续 AI 提取或更高优先级切片重新开放编辑。

### 5. 工作区单一主操作，创建入口分层

- 顶栏移除"新建节点"主按钮；"项目设置"改为图标按钮；计数统一"X 个目录节点"。
- 根节点创建由目录面板头部"＋"图标（aria：创建根节点）承担；选中节点时唯一主按钮为节点头部"创建子节点"；"编辑节点"为次要按钮。
- 移动端：非空层级头部保留"＋"图标；空状态只保留底部蓝色主按钮；节点头部新增"⋯"菜单按钮，复用现有 `NodeMenu` 能力（创建/编辑/移动到/删除），避免"提示有节点菜单但找不到入口"的不一致。

### 6. 空状态文案与按钮统一

四个空状态（桌面空目录、移动空目录、桌面空节点、移动空节点）统一说明文案"手动创建节点，不会自动采用 AI 目录。"；空目录操作统一为蓝色主按钮；空节点内容区不再重复放置按钮（桌面节点头部已有"创建子节点"主操作）。

### 7. 移动端顶栏布局

项目工作区移动顶栏改为"状态标签 + 标题一行（标题弹性占满）+ 节点数第二行弱化显示"，右侧仅保留设置与删除图标，避免标题、状态、计数与操作互相挤压。

### 8. 规格冲突处理

三处与主规格冲突的产品决定（无项目空状态、项目目标与背景合并、节点说明仅展示）以本轮设计评审决定为准，通过 delta spec 更新主规格；实现时以"规格同步 + 归档"完成闭环。若评审后续推翻任一决定，需同步回滚对应 delta。

## Risks / Trade-offs

- [背景字段不再通过 UI 暴露，但模型/API 仍接受它] → 保留兼容性，不在前端发送该字段；API 测试保持现有校验，避免破坏已有客户端。
- [节点说明 P0 不可编辑，内容区仍展示说明] → 数据由后端/后续 AI 能力提供；若出现"需要人工修正说明"的验收场景，需单独变更重新开放编辑。
- [规格变更属于行为变更] → 归档后主规格永久记录新行为；任何回退需新 Change，评审时已确认。
- [纯 CSS/组件改动涉及面广（index.css 1600+ 行）] → 分页面逐步改并逐页验收，避免一次大改导致回归；依赖现有测试 + 浏览器双视口验收。
- [无数据库/API 变更] → 无迁移与回滚风险；如需回滚仅回滚前端提交。

## Open Questions

- 登录页桌面端是否需要非数据类的品牌/价值说明面板（纯静态）？本轮默认不做，后续可按需单独变更。
- `background` 是否在后续切片中并入 `goal` 或用于 AI 生成？本轮保持现状，不决策。
