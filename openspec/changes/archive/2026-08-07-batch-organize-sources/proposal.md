## Why

采集箱里的文字、链接和图片 Source 只能逐条处理：没有批量分配到项目、批量删除、批量重试失败任务的能力，重复粘贴同一链接、同一段文字或同一张图也毫无提示，资料越积越多、整理成本居高不下。产品当前聚焦"知识采集与整理"，桌面端批量整理是这一阶段最直接的效率缺口。

## Appetite

一个垂直切片，投入约 2-3 天：1 次数据库迁移（指纹列）+ 3 个批量端点 + 采集/列表去重提示 + 前端多选 UI + 自动化测试与真实验收。不做超出该范围的能力。

## What Changes

- 新增 Source 批量操作 API：批量分配到项目、批量删除、批量重试失败任务；请求内任一标识非法/跨 Workspace/状态不允许时整批拒绝，不产生部分成功。
- 批量分配仅允许"未分配 → 分配"（一次性归属）；已分配或已被正式记录引用的 Source 不可再分配。
- 批量删除受引用保护：被 Entry 引用的 Source 整批阻断并返回阻断数量；运行中任务（Processing Task 执行中）的 Source 同样拒绝删除；删除时同步清理附件文件与数据库行。
- 批量重试仅对失败任务生效，沿用现有"从失败步骤重试、不复制 Source/候选/Entry"语义。
- 新增疑似重复采集检测：text 按空白归一化全文指纹、link 按规范化 URL 指纹、image 按文件字节指纹（SHA-256）；采集提交时提示"已有相同采集"，列表标记疑似重复（指向原 Source），不阻断采集、不自动合并或删除。
- 桌面端采集箱提供多选与批量操作条（分配/删除/重试）；移动端保持现有单条操作，仅展示疑似重复标记。

## Capabilities

### New Capabilities

- 无（全部能力归入现有采集箱能力）。

### Modified Capabilities

- `inbox-processing`：新增"批量整理 Source"与"疑似重复采集检测"两类 Requirement，覆盖批量分配/删除/重试、引用保护与指纹去重语义。

## Impact

- 后端：`sources` 表新增指纹列（迁移）；新增批量端点（分配/删除/重试）与去重查询；`inbox.py`、`services/inbox.py`、`schemas/inbox.py` 扩展；复用现有项目/节点删除的受保护引用模式。
- 前端：采集箱列表多选 UI、批量操作条、疑似重复标记与采集提交提示；`frontend/src/inbox/` 查询与类型扩展。
- 数据库：1 次 Alembic 迁移；MySQL 验证（`_test` 库）。
- 文档：`docs/` 中采集箱相关基线不做功能变化，仅在本 Change 归档后同步主规格。
