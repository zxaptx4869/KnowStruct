## Why

登录后的用户目前没有可用的业务容器，无法创建项目、组织知识目录，也无法为后续的采集、归档和搜索建立必要的 Project / Node 边界。本 Change 是已实现密码登录后的下一个 P0 垂直切片，将先建立可维护、可隔离的普通知识目录树。

## What Changes

- 提供当前个人 Workspace 内的项目列表、创建、查看、编辑、状态修改和删除能力。
- 项目状态使用“规划中、进行中、已暂停、已完成”四种可编辑阶段，新项目默认为“规划中”，状态不锁定项目内容。
- 每个项目提供最多 6 层的普通知识目录树，支持节点创建、查看、改名、说明编辑、同级排序、跨父节点移动和删除空子树。
- 桌面端提供常驻目录树和完整的移动排序交互；移动端提供逐级浏览、创建子节点和改名。
- 为无项目、空目录、空节点、加载、提交、失败与重试提供明确界面状态，并在桌面和 390px 移动视口验证同一响应式 Web 应用。
- 所有 Project / Node 读写均通过已实现的认证上下文限定到当前 Workspace，对不可见对象统一按不存在处理。
- Appetite 为单人最多 8 个工作日，不超过两个自然周；超出时优先削减目录名称筛选、拖拽动画和聚合摘要，不削减 Workspace 隔离、树完整性、桌面移动排序、异常状态和测试。
- Non-goals：不包含 AI 起草目录、AI 节点拓展、项目模板或导入、归档恢复、项目复制、最近活动、Source / Entry / Decision 管理、正式记录数量、知识图谱、跨项目节点、多人协作、复杂权限或移动端拖拽。

## Capabilities

### New Capabilities

- `project-management`: 定义当前 Workspace 内项目的创建、列表、查看、编辑、状态、删除、空状态与数据隔离。
- `knowledge-directory`: 定义项目内多级知识目录的层级约束、增删改查、排序移动、路径浏览、双端行为与树完整性。

### Modified Capabilities

- 无。`password-authentication` 仅作为当前用户和默认个人 Workspace 上下文的现有依赖，不修改其要求。

## Impact

- 后端将新增 Project / Node 持久化模型、Alembic 迁移、Pydantic schema、Workspace 限定的 FastAPI 端点、服务层树操作与自动化测试。
- 前端将替换现有项目和节点占位页，接入项目 / 目录 API，完成桌面三段式目录工作区和移动端逐级浏览。
- 数据库保持 MySQL 8.0+ 为生产基线，采用 Project 到 Node 的普通父子关系，不引入图数据库。
- 本 Change 依赖 `password-authentication` 主规格，产品边界依据文档路由中的项目与知识目录、导航与双端布局、领域模型、删除规则和验收相关章节。
