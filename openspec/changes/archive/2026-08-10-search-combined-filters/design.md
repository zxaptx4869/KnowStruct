## Context

全局搜索当前只有 `q` 关键词参数：后端 `search()` 固定按 Workspace + `Entry.status == "archived"`
过滤，Entry 与 Source 各取 50 条倒序返回；前端搜索页只有输入框，URL 仅持久化 `?q=`。
项目列表（`GET /api/projects`）与项目节点列表（`GET /api/projects/{id}/nodes`）接口已存在，
可直接作为筛选控件的选项来源。Entry 类型枚举（experience/parameter/pitfall/product/price 等）
与 Source 类型（text/link/image）均为既有字段，无需迁移。

## Goals / Non-Goals

**Goals:**

- 全局搜索支持项目、记录类型、项目内节点三个可选筛选，与关键词组合生效。
- 筛选状态通过 URL query 持久化，刷新与前进后退保持；非法参数给出可读错误并可恢复。
- 移动端 390px 与桌面端体验一致，不破坏既有高亮、上限、排序与来源证据语义。

**Non-Goals:**

- 状态筛选、语义搜索、保存搜索、结果分页扩展、筛选入搜索历史。
- 节点子树聚合、节点多选、结果分组或排序变化。
- 修改项目记录列表、整理模式等其他页面的筛选行为。

## Decisions

### 1. 筛选参数与校验（后端）

`GET /api/search` 新增三个可选查询参数：`project`、`type`、`node`（与既有 `q` 同风格短名）。

- `project`：必须是当前 Workspace 内的 Project id，否则 422 `invalid_project`。
- `type`：必须是合法 EntryType，否则 422 `invalid_type`。
- `node`：必须属于所选项目（与 `project` 一起使用）；未带 `project` 时传 `node` 视为非法，
  返回 422 `node_requires_project`。节点校验同时确认节点属于当前 Workspace（通过项目归属推导）。
- 校验失败与关键词校验一致，返回可读 message，不返回空结果集代替。

理由：短参数名与 `q` 风格一致；节点强依赖项目避免跨项目歧义；
显式 422 比静默忽略更利于前端给出可恢复的错误态。

### 2. 筛选语义

- `project`：同时约束 Entry 与 Source 命中（Source 的 `project_id` 可为空，未分配项目在项目筛选下不出现）。
- `type`：只约束 Entry 命中（Source 无记录类型字段）。
- `node`：只约束 Entry 命中，且只匹配 `node_id == node` 的记录，不含子树；
  与节点详情页、整理模式「单选节点」的既有语义一致。
- 三类筛选均叠加到关键词 LIKE 条件之上；排序、每类 50 条上限、Entry 优先展示不变。

理由：保持「Entry 为主、Source 为证据」的分层；子树聚合会引入额外查询复杂度且与既有
节点语义不一致；筛选是收窄而非重定义结果结构。

### 3. 触发语义（前端）

- 关键词输入仍显式提交（点击搜索、回车且非 IME 组合态）。
- 已有搜索结果时，变更任一筛选立即重新搜索（facet 行为）。
- 未发起过搜索（关键词为空）时，变更筛选只更新 URL 与界面状态，不发起请求。
- URL 带 `?q=` 打开页面时自动执行一次搜索；带筛选不带 `q` 时进入空态引导，不请求。

理由：结构化下拉是离散低频操作，立即应用符合直觉；关键词输入高频，保持显式提交可避免
既有规格与误触行为被破坏。

### 4. 节点选项联动

选择项目后通过 `useNodes(projectId)` 拉取节点列表；切换项目时清空已选节点并重置 `node` URL
参数。节点选项按树形缩进展示（复用现有 tree 构建工具），选项值为节点 id。
节点接口加载失败时，节点选择器显示「先选择项目」提示并允许重试，不阻塞关键词搜索。

### 5. 查询键与请求

前端 `searchKeys.query` 从 `(keyword)` 扩展为 `(keyword, project, type, node)`；
`useSearch` 仅在 `q` 非空时启用，筛选参数随请求发送。最近搜索历史仍只记录关键词
（`recordedDataRef` 逻辑不变），与既有 `recent-search-history` 主规格保持一致。

### 6. 错误与恢复

后端 422 的 `code` 透传到前端；筛选参数来自 URL 时（如手工编辑），搜索失败态保留关键词与合法
筛选，显示可读错误并提供「清除筛选」操作。常规筛选变更失败（网络/服务端）沿用既有失败态：
保留关键词与筛选、可重试。

## Risks / Trade-offs

- [节点筛选只匹配当前节点，用户可能期待子树聚合] → 与节点详情页/整理模式语义保持一致，
  在规格中明确「不含子树」，后续如需子树聚合单独变更。
- [类型/节点筛选下来源命中区仍显示关键词命中的全项目来源，可能被误解] → 来源区段保留
  证据定位，仅受项目筛选约束；在验收与规格中写明该语义。
- [筛选条件多导致 LIKE 查询计划退化] → 复用既有 `ix_entries_project`、`ix_entries_node`
  索引，且每类结果上限 50，当前数据量级可接受；后续大数据量再评估全文索引。
- [URL 被手工改成非法参数] → 后端 422 + 前端可读错误态与「清除筛选」恢复路径。
- [节点选项接口失败影响搜索页可用性] → 节点选择器独立降级，不阻塞关键词搜索。

## Migration Plan

无数据库迁移、无外部依赖变更。前后端同版部署即可；回滚为撤销本分支合并（无持久化结构变化）。
