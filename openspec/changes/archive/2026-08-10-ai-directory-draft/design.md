## Context

项目目录由普通父子 Node 组成，最大 6 层、同级标准化名称唯一、Workspace 归属由 Project 推导；
现有 nodes 服务已实现深度、重名、循环与移动校验。AI Provider 抽象已预留
`generate_outline(goal, context)` 与 `expand_node(node_title, context)` 接口，
DeepSeek/豆包实现目前为「尚未实现」占位；现有提取/审查均为无状态独立调用。
产品约束：AI 输出永远是候选、人工确认后落库；不以 AI 聊天为主入口。

## Goals / Non-Goals

**Goals:**

- 空项目内由 AI 起草候选目录，经单轮澄清、预览编辑、指令式微调与确认后批量创建节点。
- 每次 AI 调用无状态、提示词有界（不随微调轮次膨胀），增量修改保持草稿稳定。
- 单项目单草稿，与手动建目录互斥不冲突。

**Non-Goals:**

- C7 节点拓展、静态模板、非空项目合并、对话式共创、AI 自动建节点。

## Decisions

### 1. 数据模型（新表 + 迁移）

- `directory_drafts`：一次起草；字段含 project_id（Workspace 经 Project 推导）、status、
  background_snapshot、intent_note（当前意图说明）、created_at/updated_at。
- `directory_draft_nodes`：草稿树节点；parent_id（同表自引用）、name、description、
  selected（用户勾选）、sort_order；确认时按 selected 及祖先自动包含创建正式 Node。
- 状态：drafting（起草中）/ awaiting_input（待澄清）/ pending_confirm（待确认）/
  failed（起草失败，可重试）/ confirmed（已确认）/ discarded（已放弃）。
- 唯一约束：同一 project 同时至多 1 条非终态草稿（服务层事务校验，MySQL 不支持部分唯一索引）。
- 迁移 + 真实 MySQL 验证；正式 Node 不落库前草稿可安全删除。

### 2. AI 调用设计（无状态、有界、增量）

每次均为独立 `chat.completions.create` 调用，应用不维护会话历史：

- 起草：system 提示 + `项目目标/背景 + Source 摘要（限长）+ 澄清答案` → 候选树 JSON。
- 澄清：独立调用输出「是否充足 + 问题列表（≤3-5，选项为主）」，可跳过。
- 微调：`当前草稿 JSON + 当前意图说明 + 本次意见` → **增量改动清单**（新增/改名/删除/移动），
  提示词明示未提及节点原样保留；微调轮次不发背景与 Source。
- 重新起草：更新背景快照后按起草调用重新生成，旧草稿可选保留版本。
- 意图浓缩（可选）：确认微调后调用一次将旧说明+本次意见浓缩为一段；失败时回退为追加原文。
- 校验：结构/名称/深度/重名失败 → 草稿 failed 可重试，不静默裁剪。

理由：无状态避免窗口膨胀与成本失控；状态快照+意图说明双载体代替对话记忆；
增量清单把「最新意图 > 草稿 > 背景」的优先级显式化。

### 3. 确认与冲突规则

- 确认采用：以 selected + 祖先自动包含的结果，在单事务内调用既有 nodes 校验创建；
  任一节点失败整批回滚，草稿保持 pending_confirm 可重试；成功置 confirmed。
- 手动创建节点：目录出现手动节点前，若存在活跃草稿，弹出确认「创建节点将放弃当前 AI 草稿」；
  确认后草稿置 discarded 并创建节点；取消则回到草稿处理。
- 有活跃草稿时隐藏「AI 起草目录」入口，显示「继续处理 / 放弃草稿」。

### 4. 前端界面（同一响应式面板）

- 空目录态：说明 + 「创建第一个节点」+「AI 起草目录」（主色按钮）。
- 起草面板内嵌项目页目录区：澄清步（问题卡片，可跳过）→ 起草进度 → 候选预览/编辑
  （复选框、内联改名、删除、调整意见框 + 重新生成）→ 确认采用/放弃。
- 离开后回项目：显示「有 AI 草稿待处理」入口，恢复面板对应状态。
- 移动端：同面板纵向排布，全流程可用。

### 5. 安全与数据归属

- 所有草稿读写经 project_id 推导 Workspace；跨 Workspace 请求按不存在处理。
- 草稿字段不含完整 Source 原文（仅后端组装限长摘要），响应不返回原始背景外的多余数据。
- 重试幂等：失败重试不重复创建草稿或节点；确认重复提交返回原结果。

## Risks / Trade-offs

- [AI 目录质量不确定] → 候选+人工确认门槛；默认全选便于快速采纳，确认前可整体放弃。
- [澄清问题惹反感] → 仅信息不足时出现、≤3-5 题、选项为主、可跳过。
- [增量修改仍可能偏离] → 提示词显式「未提及原样保留」+ 意图说明最高优先级；大改走重新起草。
- [提示词膨胀] → Source 限长摘要；微调轮次不发背景；意图说明浓缩（可选）。
- [并发冲突] → 单草稿约束 + 手动创建确认作废，草稿与正式树永不并存。
- [实现范围偏大] → 澄清/意图浓缩均设「可跳过/可降级」路径；MVP 可先固定短问卷与追加式意图说明。

## Migration Plan

- 新增 `directory_drafts`、`directory_draft_nodes` 表；迁移在真实 MySQL 验证后提交。
- 无外部依赖新增；回滚为撤销合并（新表由迁移回滚删除，正式 Node 未受影响）。
