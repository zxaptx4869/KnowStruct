## Context

搜索页当前为 300ms 防抖自动搜索：输入变化即触发请求并按成功结果记录历史，导致输入法组合中的拼音与中途提交词进入历史。历史以逐行列表展示（每行一个关键词 + 删除按钮）。低保真原型中的搜索页本就有显式"搜索"按钮，本次回归该交互形态，并将历史改为标签流。

后端 `GET /api/search?q=` 无改动；历史存储模块 `frontend/src/search/history.ts`（去重置顶、8 条上限、按用户隔离、静默降级）保持不变，仅调整触发时机与展示形态。

## Goals / Non-Goals

**Goals:**
- 搜索仅由显式提交触发（搜索按钮 / 回车），输入变化不自动请求，彻底消除拼音与中间词进入历史的路径。
- 组合状态中的回车不触发搜索；空关键词提交给出提示。
- 搜索结果展示后编辑输入框保留旧结果与 URL 关键词，清空输入回到空态。
- 最近搜索以自适应宽度的标签流展示，含单条删除与清空；桌面与 390px 移动端可用。

**Non-Goals:**
- 不改后端搜索接口与查询语义。
- 不做"最近查看"、跨设备同步、搜索统计等 P1-P3 能力。
- 不改变记录语义（成功含无结果记录、失败不记录、去重置顶、8 条上限）。

## Decisions

### 1. 显式提交触发搜索，移除防抖自动搜索

`keyword` 状态只在提交时更新：点击"搜索"按钮、输入框回车（非组合状态）、点击历史标签、URL 恢复。`input` 与 `keyword` 解耦：输入变化只改 `input`，不触发请求。

- 提交时同步 URL：`setSearchParams({ q: keyword }, { replace: true })`；清空输入时移除参数。
- 理由：与低保真原型一致，移动端虚拟键盘"搜索"键 + 按钮双入口，且记录逻辑天然只收到完整词。
- 备选：保留自动搜索、仅抑制记录——拼音仍会被真实搜索并闪空态，否决。

### 2. 输入法组合保护

用 `composingRef` 跟踪 `onCompositionStart/End`；回车处理同时校验 `event.nativeEvent.isComposing` 与 `composingRef`，组合中回车 MUST 被忽略。

- 理由：桌面浏览器组合期间 keydown 以 `isComposing=true`/keyCode 229 到达页面；移动虚拟键盘"搜索"键在组合期间行为因输入法而异。双保险覆盖两类环境。
- 用户常见流程（空格选词、回车发送）不受影响：回车时组合已结束。

### 3. 编辑保留旧结果，清空回空态

- 提交后修改输入框但不提交：`keyword` 与 URL 不变，旧结果继续展示。
- 输入框变为空：`keyword` 与 URL 清空，页面回到引导/最近搜索态。
- 理由：避免输入一半结果乱闪；清空是明确的"回到起点"语义。

### 4. URL 恢复仍自动搜索一次

`keyword` 初始值来自 `urlKeyword`，挂载即触发一次搜索并按规定记录；外部 URL 变化（深链/返回）沿用现有同步 effect 更新输入与关键词。

### 5. 历史标签流

用 `display: flex; flex-wrap: wrap` 容器铺开标签，按内容宽度自适应；每个标签为两个并列按钮（关键词按钮 + X 删除按钮），避免 button 嵌套：

- 标签高约 40px，X 独立可点（移动端不额外缩小触控区）；长词允许占满整行换行。
- 区块头部保留"最近搜索"标题与"清空"按钮；输入框非空时隐藏区块。
- 点击关键词标签 = 回填输入框并立即提交搜索（该词按记录规则置顶）。

### 6. 记录语义保持不变

沿用 `addSearch/removeSearch/clearHistory`：搜索成功（含无结果）记录、失败不记录、去重置顶、上限 8 条、按用户隔离；记录 effect 幂等守卫继续生效。

## Risks / Trade-offs

- [编辑旧结果与输入不一致] → 提交前旧结果持续可见；清空输入即回空态，可预期。
- [移动端"搜索"键行为差异] → 组合守卫 + 显式按钮双保险；即使某输入法提交时 keydown 未到页面，用户再按一次即可。
- [标签 X 触控区偏小] → 标签整体高约 40px，X 按钮与关键词按钮等高；390px 验收覆盖点击。
- [回车重复提交] → 组合守卫避免选词误触；重复按回车只是重复执行同一查询并置顶，无副作用。

## Migration Plan

- 无后端与数据模型变更；前端随版本发布，历史数据结构不变。
- 回滚：整体回退该提交；历史键残留无害。
